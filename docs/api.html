What a plugin is and how it runs

A plugin is a small program added to Bunker servers: it replies to commands, listens to events (messages, voice channels, members), stores data, plays music/radio in voice channels and shows its own window in the panel.

  you ── upload code ──▶  Bunker (restricted environment)  ──▶  servers you added the plugin to
                                   │
                                   └─ only what the SDK offers (the permissions you were granted)
  • The code runs on Bunker, in a separate restricted environment per plugin. It has no internet or file access; its only connection to the outside is the SDK.
  • A plugin runs only on servers it was added to and only sees those servers' events. It never sees direct messages (DMs).
  • The server owner sees the requested permissions and approves them when adding the plugin.
  • A new plugin is unverified: it can only be added to servers you manage, and it runs as soon as you upload it. To make it public, have the Bunker team review it (Publishing to the Store).

A plugin that doesn't follow these rules is rejected or won't run.

Code

  • A single file. You can't import other files; bundle the libraries you use into one file (First plugin, step 2).
  • The file must export default definePlugin({ setup(ctx) { … } }).
  • The only external import: @bunker-community/plugin-sdk.
  • Don't call connect(); Bunker connects the plugin (connect is only for testing on your computer).

What the environment forbids

ForbiddenDescription
InternetNo fetch, WebSocket, http, https, net, dns… You can't call external APIs.
File systemNo fs, os, child_process, worker_threads, vm. Use Storage for persistent data.
Environment variablesEmpty. There is nowhere to put secret keys (and no internet to use them anyway).
Resources128 MB memory; if the 1-minute CPU average exceeds 40% or it doesn't respond for 20 s (infinite loop), the plugin is killed and restarted. After 5 crashes in 10 minutes it stops.

A plugin that needs the internet (weather, exchange rates…) can currently only run on your own computer.

Permissions

Ask only for what you need; server owners won't add plugins that ask for too much, and the Store review rejects them. An action without permission throws.

PermissionShown to the server ownerUnlocks

chat.sendPosts messages in text channels under its own namectx.chat.send, c.reply

events.membersSees members joining and leaving the servermember.*, guild.create/delete

ctx.log, ctx.ui and the guild.install/uninstall events need no permission. If an update adds a new permission, the plugin stops on every server it is installed on until that server's owner approves it again.

Your first plugin: write, upload, run

1. Write two files.

bunker-plugin.json

{
  "name": "Dice Bot",
  "version": "1.0.0",
  "description": "Rolls dice: !roll 20",
  "sdk": "0.1",
  "permissions": ["events.messages", "chat.send"]
}

plugin.js

import { definePlugin } from "@bunker-community/plugin-sdk";

export default definePlugin({
  setup(ctx) {
    ctx.command("roll", async (c) => {
      const sides = Math.max(2, Math.min(1000, Number(c.args) || 6));
      await c.reply(`${c.nick} rolled ${1 + Math.floor(Math.random() * sides)} (d${sides})`);
    });
  },
});

2. Bundle into one file. If you use no libraries, plugin.js already is a single file; skip this step. Otherwise (Node.js 22+):

npm install @bunker-community/plugin-sdk
npx esbuild plugin.js --bundle --format=esm --platform=neutral --external:@bunker-community/plugin-sdk --outfile=bundle.mjs

3. Create it on Bunker and upload.

  1. Settings → Developer → New plugin: type a name, Create. (Keep the token shown; you only need it for testing from your computer.)
  2. On the plugin's row, Upload code: select the code file and bunker-plugin.json (plus the .html if it has a window) together.
  3. Run on Bunker. The row shows "Connected (running on Bunker)".

4. Add it to your server. On your server: Server settings → Plugins (or the Plugin Store) → Add → approve the permissions. Type !roll 20 in a channel.

When you change the code, bundle again and Upload new code: the new code takes effect immediately.

Testing while developing: connecting from your computer

Instead of uploading after every change, you can run the code on your computer and connect it to Bunker. The plugin works on the same servers with the same permissions; only the code runs on your machine (and can use the internet).

npm install @bunker-community/plugin-sdk

local.js (with "type": "module" in package.json)

import { connect } from "@bunker-community/plugin-sdk";
import plugin from "./plugin.js";

connect(plugin, { token: process.env.BUNKER_TOKEN });
BUNKER_TOKEN=<token> node local.js
# PowerShell: $env:BUNKER_TOKEN="<token>"; node local.js
  • The token is shown once when you create the plugin under Settings → Developer; if you lose it, use Regenerate token. Don't put it in code or share it.
  • connect sends bunker-plugin.json and the window page from the folder to Bunker on every connect.
  • While the plugin runs on Bunker you can't connect from your computer (code 4004); click Stop on its row first.
  • While your code isn't running, the bot shows offline and commands get no reply.

connect(plugin, options)

OptionDescription
tokenRequired. The plugin's token.
urlGateway address; default wss://bunker.community/app/api/plugin/gateway.
manifestManifest object; if omitted, bunker-plugin.json in dir is read.
dirFolder of bunker-plugin.json and the window page (default: working directory).
uiPageHTML of the window page (if omitted, the ui.page file is read).
loggerConnection logs (default console).

Returns { ready: Promise<void>, connected: boolean, close(): Promise<void> }. Reconnects by itself if the connection drops (1 s → 30 s). Does not retry, and ready rejects, if the token is invalid, the plugin was disabled, the manifest is invalid or the plugin is running on Bunker. This way you can't send raw PCM to voice channels (no playPcm); playMedia and playUrl work.

Lifecycle

export default definePlugin({
  async setup(ctx) {
    // Runs once when the plugin starts: set up commands and listeners here.
    ctx.onUnload(async () => {
      // On shutdown: stop timers, save state to storage if needed.
    });
  },
});
  • If setup throws, the plugin doesn't start (the reason shows under Settings → Developer).
  • When the plugin stops (stop, new code, Bunker restart): listeners are released, voice sessions close, onUnload runs. Storage still works inside onUnload; at most 3 s in total.
  • Error budget: if your listeners throw 10 errors within 60 s, the plugin stops itself. Catch your errors.
  • After the plugin stops, every call on the old ctx throws plugin kapalı ("plugin closed").

interface PluginMessage {
  id: string; ts: number; uid: string; nick: string;
  text: string;         // raw text: mentions <@uid>, custom emoji <:name:id>
  system: boolean;      // system line such as "… pinned a message"
  bot: boolean;         // written by a bot/plugin (including yours: avoid reply loops)
  attachments: number;  // number of images/videos
  replyTo?: string; edited?: number;
}

Events arrive after Bunker has finished its work; a slow listener never blocks Bunker.

Commands: ctx.command(name, fn)

ctx.command("hello", (c) => c.reply(`Hello ${c.nick}!`));
  • Name: letters, digits, _, -; 1-32 characters; written without !; lowercased.
  • Triggered only in text channels and only when a human writes it.
  • Bunker's own commands (!play, !skip, !rank, !bug…) and names taken by another plugin can't be used.
interface CommandCall {
  gid: string; chan: string; uid: string; nick: string;
  args: string;                       // text after the command
  m: PluginMessage;
  reply(text: string): Promise<void>; // to the same channel (needs chat.send)
}

Messages: ctx.chat.send(channel, text)

const r = await ctx.chat.send(chanId, "Hello!"); // { id } | null

Only to text channels of servers you were added to; shown under the bot's name with a BOT tag. At most 10 messages per 10 s. Text at most 1800 characters (longer is cut). Mentions: <@uid>.

Storage: ctx.storage

await ctx.storage.set("config:" + gid, { lang: "en" });
const a = await ctx.storage.get("config:" + gid);   // undefined if missing
await ctx.storage.delete("config:" + gid);
const keys = await ctx.storage.keys("config:");
FunctionReturns
get(key)value or undefined
set(key, value)— (value must be JSON-serializable)
delete(key)—
keys(prefix?)string[]

Private to the plugin, persistent. Values ≤64 KB, keys 1-200 characters, at most 10,000 keys. One store for all servers: prefix per-server data with gid and delete it on guild.uninstall.

Voice: ctx.voice

const s = await ctx.voice.join(cid);     // same session if already there
s.setVolume(30);
s.on("meta", (m) => ctx.log.info("playing: " + m.title));
s.on("error", (why, { silent }) => { if (!silent) ctx.log.warn(why); });
await s.playMedia("daft punk one more time");

ctx.voice.session(cid) returns the open session (or null). The bot shows up as a separate member in the channel.

VoiceSessionDescription
gid, cid, playing, paused, volume (0-100), connectedState (read-only).
playMedia(query, { seek? })YouTube / SoundCloud link, radio stream or search text. Track info arrives via the meta event.
prefetch(query)Prepare the next track (faster transitions; valid for 30 min).
playUrl(url, { seek? })Direct http(s) audio URL (radio, mp3).
stop(), pause(), resume(), setVolume(v)Controls.

interface MediaMeta { title: string; artist: string; duration: number /* s, 0 for live */; thumb: string; src: string; url: string }

If error has silent: true (e.g. YouTube blocking), you don't need to show it to users. The session closes 60 s after nobody is left in the channel, and immediately when the channel is deleted (leave). At most 12 plugin voice sessions across Bunker at once.

Window: ctx.ui

A plugin can show an icon in the plugin group at the bottom left of the panel, and a window that opens on click.

FieldDescription

Model: state down, actions up. The page cannot connect anywhere by itself; all logic lives in the plugin.

plugin ── ctx.ui.setState ──▶ panel ── {bunker:"state"} ──▶ page
plugin ◀── ctx.ui.onAction ── panel ◀── {bunker:"action"} ── page
FunctionDescription
ctx.ui.setState({ gid, cid? }, state, { live? })Sends the state to everyone on that server (in that channel for scope voice); people opening it later get the latest state too. JSON, ≤32 KB. live: true → the icon lights up. null → clear. Kept in memory.
ctx.ui.onAction(fn)fn({ gid, cid?, uid, nick, name, data }). Bunker checks the user is a member (and in the channel for scope voice); ≤10 per second per user, data ≤4 KB. Still validate data.
ctx.ui.onAction(async (a) => {
  if (a.name === "roll") ctx.ui.setState({ gid: a.gid }, { last: a.nick, result: 1 + Math.floor(Math.random() * 6) });
});

Publishing to the Store

An unverified plugin only runs on your servers and only you see it in the Store (with an "Unverified" tag). To let everyone add it:

  1. Make sure it works well on your own server.
  2. Contact the Bunker team (support@bunker.community) with the plugin's name and id (ext-…).
  3. The team reviews the code. If approved, it becomes visible to everyone in the Store (verified).

The review checks: whether the requested permissions are really needed, whether the description is accurate, whether there is misleading / harassing / spamming behavior, and whether the code is readable (deliberately obfuscated code is rejected).

Once in the Store, every new upload is reviewed too; the previously approved version keeps running until the new one is approved. Abusive plugins are disabled.

FAQ

My plugin doesn't respond. Is its row "Connected" under Settings → Developer? Is it added under Server settings → Plugins, and is there a "needs new permission" warning? Is the command name right? The error line shows the reason.

I need to call an external API. Code running on Bunker can't reach the internet. Run it on your own computer / server with connect (testing section); it can run that way permanently too.

Can I use TypeScript? Yes; esbuild compiles TypeScript while bundling. Types are included (import type { PluginContext } from "@bunker-community/plugin-sdk").

How do I store per-user settings? Put the server and user id in the key: ctx.storage.set("config:" + gid + ":" + uid, …).

I lost / leaked my token. Settings → Developer → Regenerate token; the old one stops working immediately.

Appendix A: Gateway protocol (other languages)

The SDK is for Node.js. To write a bot in another language (Python, Go…) that runs on your own machine, connect to the gateway directly: WebSocket wss://bunker.community/app/api/plugin/gateway, JSON text messages, ≤320 KB per message, ~30 calls per second.

Hello (first message, within 10 s) and reply:

{ "op": "hello", "token": "ext-…", "sdk": "0.1.4", "manifest": { "name": "…", "version": "1.0.0", "sdk": "0.1", "permissions": [] }, "uiPage": "<!doctype html>…" }
{ "op": "ready", "v": 1, "sdk": "0.1.4", "manifest": { "…": "…" }, "guilds": [{ "gid": "…", "name": "…" }] }

{ "op": "call", "id": 7, "method": "chat.send", "args": ["<channel>", "hello"] }
{ "op": "result", "id": 7, "ok": true, "value": { "id": "<message>" } }

From the server:

To reply to a command, chat.send to call.chan. Subscriptions are dropped when the connection closes; send them again after reconnecting.

Close codes: 4001 invalid / regenerated token · 4002 malformed message · 4003 plugin disabled or deleted · 4004 another connection with the same token, or the plugin is running on Bunker · 4005 invalid manifest (reason in reason) · 4008 too fast or not reading messages. Reconnect on any other close.
